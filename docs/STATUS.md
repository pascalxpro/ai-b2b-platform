## 二、關鍵背景:Gemini 為何走瀏覽器端

**Gemini API 從 Zeabur 伺服器呼叫一定失敗**,回 `400 FAILED_PRECONDITION
— User location is not supported`。

實測確認過的事實(不要再重新診斷):

| 檢查項目 | 結果 |
|---|---|
| 伺服器 IP 地理位置 | **Tokyo, JP**——是 Gemini 支援地區,所以**不是國家限制** |
| ASN | `AS132203`(Tencent)——**機房 IP**,這才是被擋的原因 |
| 同一把金鑰從台灣瀏覽器呼叫 | **成功**,證明與金鑰、方案、額度無關 |

因此系統有 `aiCallMode` 設定,`browser` 模式讓**每位使用者用自己的金鑰**從自己的
瀏覽器呼叫,金鑰只存在各自的 localStorage。每人各自擁有免費額度(Flash Lite
每日 500 次),不必共用。

**推論**:本地模型(Ollama / LM Studio)在伺服端模式**永遠不可能運作**,
因為那裡的 `localhost:11434` 是容器自己,不是使用者的電腦。

## 三、已做過的設計決策(請勿無意間推翻)

### 國別驗證只用電話,不用地址
電話有國際標準格式可靠解析;地址格式各國不同(日本由大到小、美國由小到大、
郵遞區號規則各異),需要一堆易碎的各國規則,投報率不佳。這是明確的決定。

### 只採信「國際格式」電話號碼
只接受帶國碼的號碼(`+81…`)。曾嘗試用目標國家當「預設地區」來驗證本地格式
號碼,但實測發現 **`02-2345-6789` 在日本與台灣的電話規則下都會被判定為「合理」**
——`isValid()` 只檢查格式是否可能,不證明來源國。若採用會重新製造出這個功能
本來要消除的誤判。代價是召回率降低,但「抓不到」只會退回「未驗證」(無害),
而誤判國別正是要解決的問題。

### 通用網域(.com/.net/.org)保留但標記,不排除
很多在地廠商為了國際化也用 `.com`。系統標為「未驗證」交由人工複核,
**不會直接丟棄**。

### 一次搜尋只鎖定一個國家
多國一起搜尋要為每個國家各花一次 AI token,最後卻只能合併成一條查詢——而一條
查詢只帶得動一組 `gl`/`hl`,所以多出來的國家是花錢買到更差的結果。目標國家改為
下拉單選(來源 `src/lib/search/countries.ts`),`criteriaJson.countries` 仍是陣列
以相容舊資料,但只有第 0 筆有作用。

### 國家資料只有一份
`src/lib/search/countries.ts` 是唯一來源(語言、TLD、`gl`/`hl`、公司型態後綴)。
先前散在三處且已經走鐘:searchService 有 18 國、ai/prompts 只有 10 國,選到缺的
8 國之一時 prompt 會變成「translate into 義大利」。**新增國家只改這一個檔案。**

### AI 優化的產出是「查詢式陣列」,不是一句描述
`buildOptimizePrompt` 要求回 4 條 3–7 個詞的查詢式。整句描述會命中文章和名錄,
這正是部落格排行文勝過真正廠商官網的原因。prompt 內含一組日文 few-shot 範例——
對 Flash Lite 這種小模型,「用當地人真的會用的詞」這種抽象指令沒有範例就會退化成
直譯。temperature 用 0.7(不是 0.4),因為要的是四個不同角度而非四種改寫。

### 付費 API 一條查詢,免費爬蟲跑全部
API 引擎只送 `queries[0]`,所以啟用優化不會增加 API 花費;Yahoo/DDG/Bing 爬蟲免費,
就把 4 條都跑一遍換取涵蓋率。

### 結果各帳號私有,共享要「明確釋放」而非預設開放
結果池不做共享資料表。每筆結果有 `ownerUserId`,預設只有擁有者看得到;
要交給別人必須主動釋放到商機池。**可見性與可修改性是兩回事**——釋放後大家都
看得到,但編輯權仍只屬於擁有者(`visibilityFilter` 與 `mutabilityFilter`,
定義在 `src/lib/search/ownership.ts`)。

### 認領用「條件式 updateMany」而非先讀再寫
`where` 裡再檢查一次 `poolState: 'RELEASED'`,所以兩人同時認領時只有一筆會
match,另一筆 count 為 0 並回報「已被先行認領」。不要改成 findFirst 後 update,
那會有 race condition,結果是兩個業務同時接觸同一家客戶。

### `detectCountry()` 絕不 fallback 成「使用者搜尋的國家」
這個 fallback 曾是「搜日本卻顯示台灣公司為日本」的直接原因。查不到就回 `null`。

## 四、已知未完成 / 刻意延後

- **workspace 層級授權**:搜尋結果已改為依帳號歸屬(commit `1b78823`),

- **跨帳號去重**:認領時只比對「認領者自己的結果池是否已有同網域公司」。
  全公司層級的 CanonicalCompany 去重刻意延後。
- **本地模型優先順序**(LM Studio → Ollama → Gemini):已設計未實作。
  現有 `aiProvider` 是單選、`aiBaseUrl` 只有一個欄位,無法同時設定兩者。
  實測確認 HTTPS 頁面**可以**連 `http://localhost`(瀏覽器豁免 localhost 的
  混合內容限制,與多數網路文章的說法相反),所以瀏覽端模式下技術可行,
  但需在 Ollama 設 `OLLAMA_ORIGINS`。
- **產業/類型欄位**:搜尋引擎不提供這些資料,目前只有人工編輯才會有值。
- **Google Custom Search**:官方已**停止對新客戶開放**,且 2027-01-01 終止服務。
  已決定不使用,請勿再花時間設定。
- **其他模組**(客戶與商機、任務中心、會議智慧等):階段一刻意未完成的骨架,
  不是缺陷。
